How the video machine works

It works like a print shop where every frame is a web page. Claude writes each scene in HTML, a robot browser photographs it 30 times a second, and those photos become the MP4. Every ad is a text file, so changing a word or a colour means editing the file and rendering again.

The line, start to finish

0You drop reels

A reel or a folder. You say "recreate this" or /recreate-reel.

1Breakdown

Frames every 0.5s, scene cuts, transcript. Claude writes BEATS.md: what moves, when, how fast.

2Angle + proof

One Limitless copy angle and one verified proof per ad, rotated so ads don't repeat.

3Script + copy check

Black Card lines word for word. check_copy.py flags new lines, banned words, 108/84 and the 30-day guarantee.

4Build

Starter template + moves library + our product clips + HyperFrames effects. Animation is GSAP.

5Render

render.sh: one render at a time (a lock file), 1080x1920, 30fps, silent.

6Self-check

12-frame contact sheet. Fix overlap, cut-off text, sparse frames, missing SAMPLE chips.

7You review

Claude sends the MP4 and its flags. "Good, next one" or "changes first". "Finished" shelves it.

Two modes. One at a time (the default): you see each ad before the next one starts. Batch: one builder per reel, all running at once. They wait their turn for the render, so the Mac isn't hit with 7 renders together.
